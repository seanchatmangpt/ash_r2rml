# AshR2ML benchmarks

AshR2ML benchmarks measure semantic compilation and virtual-RDF integration costs. They do not benchmark Neo4j, Cypher, graph indexes, vector search, or spatial pushdown.

The donor-era benchmark scripts currently present in this directory are historical implementation artifacts and are not part of the finished AshR2ML benchmark contract. They should be removed or replaced as the runtime migration lands.

## Benchmark classes

### Mapping compilation

Measure compilation from Ash resources into the normalized `AshR2ML.Mapping` IR.

Dimensions:

- number of resources;
- attributes per resource;
- relationships per resource;
- composite identities;
- custom datatype mappings;
- named graph mappings.

Report throughput and allocation behavior separately from R2RML serialization.

### R2RML rendering

Measure deterministic Turtle generation from a prebuilt normalized IR.

The renderer benchmark must not include Ash resource introspection when the claim is renderer-only.

### Ontology-first manufacture

Measure ggen construction from admitted ontology/profile/SHACL input to generated Ash resources and mapping artifacts.

Record:

- graph size;
- shape/property count;
- gate time;
- query time;
- render time;
- total generated bytes/files;
- deterministic second-run comparison.

### OBDA integration

Measure SPARQL query latency only as an integration benchmark and always name the external OBDA engine, database, dataset, query corpus, indexes, and warm/cold conditions.

Do not attribute OBDA query-planning performance to AshR2ML itself. AshR2ML's responsibility is the correctness and quality of the generated mapping.

## Correctness before speed

A benchmark result is invalid if the optimized path changes semantic results.

Every benchmark corpus used for performance claims must first pass the semantic conformance fixture for subject identity, literals, and mapped relationships.

## Determinism benchmark

Run the same compiler/render input repeatedly and assert byte-identical semantic output. Performance improvements may not introduce iteration-order nondeterminism.

## Representative scale tiers

Use connected resource graphs rather than isolated scalar-only resources.

Recommended tiers:

| Tier | Resources | Properties | Relationships | Purpose |
|---|---:|---:|---:|---|
| small | 10 | ~100 | ~20 | local regression |
| medium | 100 | ~1,000 | ~250 | application-scale compiler behavior |
| large | 1,000 | ~10,000 | ~2,500 | generator/renderer scaling |

These are corpus sizes, not product limits.

## Reporting

Every published benchmark result must include:

- exact commit SHA;
- Elixir/OTP versions;
- Ash/AshR2ML versions;
- ggen version when involved;
- PostgreSQL and OBDA versions when involved;
- fixture digest;
- command line;
- warmup/sample methodology;
- correctness verifier run before timing.

Performance without semantic equivalence evidence is not an AshR2ML result.
