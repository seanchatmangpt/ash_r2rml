# Production usage rules

- Treat enterprise scale as a measurable quality profile, never as a semantic domain name.
- Keep `AshR2RML.DfCM` independent of deployment vendors and organizational tiers.
- Do not collapse the DfCM candidate set until constraints or explicit authority select a candidate.
- Do not promote generated files, CI metadata, unit tests, or model output to runtime evidence.
- Bind every production evidence item to the exact semantic subject and stable receipt identity.
- Keep technical production standing separate from deployment/cutover authority.
- Require BRCE for every DO operation.
- Let ggen own final manufacturing; Elixir constructs dynamic admitted inputs and receipts.
- Never check in a second hand-maintained application ontology under `production/ggen`.
- Fail closed on unknown quota state, missing residency context, unbounded execution, evidence mismatch, high/critical dependency vulnerabilities, and stale receipts.
