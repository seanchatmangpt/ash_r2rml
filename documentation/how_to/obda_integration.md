# How to Integrate AshR2RML with OBDA & Virtual RDF Query Engines

This guide demonstrates how to configure an Ontology-Based Data Access (OBDA) engine (such as Ontop, GraphDB, or Stardog) to execute virtual SPARQL queries against relational tables managed by `AshPostgres` using R2RML mappings generated by `AshR2RML`.

---

## Architectural Context

```text
SPARQL Query
     │
     ▼
OBDA Engine (Ontop / GraphDB)
     │  (reads AshR2RML generated Turtle)
     ▼
SQL Query Rewriting
     │
     ▼
PostgreSQL Database (managed by AshPostgres)
     │
     ▼
Unified RDF Result Set (matches Ash resource state)
```

---

## Step 1: Export R2RML Turtle Artifacts

Create a mix task or script to export R2RML Turtle mappings for all annotated resources:

```elixir
defmodule Mix.Tasks.AshR2rml.Export do
  use Mix.Task

  @shortdoc "Exports R2RML Turtle for all annotated Ash resources"

  def run(_args) do
    Mix.Task.run("app.start")

    resources = [
      MyApp.User,
      MyApp.Organization
    ]

    {:ok, turtle_strings} =
      resources
      |> Enum.map(fn res ->
        {:ok, mapping} = AshR2RML.Mapping.from_resource(res)
        {:ok, turtle} = AshR2RML.R2RML.Renderer.render(mapping)
        turtle
      end)
      |> Enum.join("\n\n")

    File.write!("priv/r2rml/mapping.ttl", turtle_strings)
    Mix.shell().info("R2RML mapping successfully exported to priv/r2rml/mapping.ttl")
  end
end
```

Run the export:

```sh
mix ash_r2rml.export
```

---

## Step 2: Configure OBDA Engine Database Connection

Create an `.properties` file for your OBDA engine (e.g. `ontop.properties`):

```properties
jdbc.url=jdbc:postgresql://localhost:5432/my_app_repo
jdbc.driver=org.postgresql.Driver
jdbc.user=postgres
jdbc.password=postgres
ontop.mapping.file=priv/r2rml/mapping.ttl
```

---

## Step 3: Execute Virtual SPARQL Queries

Start the OBDA endpoint using Ontop CLI or Docker:

```sh
docker run --rm -p 8080:8080 \
  -v $(pwd)/priv/r2rml/mapping.ttl:/opt/ontop/mapping.ttl \
  -v $(pwd)/ontop.properties:/opt/ontop/input/ontop.properties \
  ontop/ontop-endpoint
```

Submit a SPARQL query over HTTP:

```sparql
PREFIX schema: <https://schema.org/>
PREFIX foaf: <http://xmlns.com/foaf/0.1/>

SELECT ?person ?name ?orgName WHERE {
  ?person a schema:Person ;
          foaf:name ?name ;
          schema:memberOf ?org .
  ?org schema:name ?orgName .
}
```

---

## Step 4: Verify Semantic Round-Trip Invariant

Confirm that data retrieved via SPARQL yields identical subject IRIs and attribute values as those queried directly through Ash resource actions:

```elixir
# Ash query check
user = Ash.get!(MyApp.User, user_id, load: [:organization])

# Verification invariant:
# user.name == SPARQL ?name
# "https://example.org/users/#{user.id}" == SPARQL ?person IRI
```

If SPARQL results disagree with Ash-visible relational state, verify that column projections and join conditions match your database migrations.
