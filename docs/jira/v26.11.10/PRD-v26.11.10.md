## 1. Product Outcome

AshR2RML compiles RDF/OWL/SKOS ontologies and SHACL profiles directly into production-grade Ash 3.0 systems. Specifically, downstream developers can:
1. Declare governing Ash 3.0 `Ash.Domain` modules via `r2ml:domainModule` on SHACL node shapes.
2. Synthesize bidirectional navigability via `r2ml:inverseName` generating typed `has_many` inverses on target resources.
3. Emit modular file-system layouts (`files: :per_resource`) with individual `.ex` files for each domain and resource, accompanied by cryptographic `ash-file-set.json` receipts.
4. Verify bilateral trust with consumer packs via the `castle_bridge_contract.ttl` trust mirror.
5. Depend on a certified Hex package (`v26.11.10`) validated via clean compilation, strict formatting, complete test suite passage, and 5-persona architectural review.

---

## 2. Problem Statement

Prior to v26.11.10:
- **Ash 3.0 Domain Gap**: Generated resources defaulted to `domain: nil`. Ash 3.0 enforces domain governance; un-scoped resources required manual post-generation boilerplate to assemble into domains.
- **Unidirectional Edge Bottleneck**: RDF object properties are inherently directed (`Source -> Destination`). Navigating relationships backwards (e.g., retrieving all `Clients` for a given `Party`) required manual inverse relationship definitions.
- **Monolithic File Generation**: Code generation produced a single monolithic output file `generated/ash/ontology_resources.ex`, which resisted standard Elixir code organization and module-per-file conventions.
- **Asymmetric Trust**: Downstream consumer packs pinned `ash_r2rml`, but `ash_r2rml` maintained no reciprocal observation of consumer contracts, risking breaking downstream contracts silently.
- **Documentation Drift**: Documentation commit pins became stale as development advanced on `dev`, requiring automated ancestry courts to prevent stale commit references from landing in releases.

## 3. Functional Requirements

### FR1. Ash 3.0 Domain Module Projection (`r2ml:domainModule`)
- **FR1.1**: Ingest optional `r2ml:domainModule` literal from SHACL `sh:NodeShape` definitions.
- **FR1.2**: Persist `:domain` in `AshR2RML.SemanticIR.Resource`.
- **FR1.3**: Validate module naming syntax at admission time via `AshR2RML.Admission.verify_domain/1` using regex `~r/\A[A-Z][A-Za-z0-9_]*(\.[A-Z][A-Za-z0-9_]*)*\z/`. Refuse malformed names with `:REFUSED_UNPROVEN_EQUIVALENCE`.
- **FR1.4**: Synthesize governing `Ash.Domain` modules (`use Ash.Domain, validate_config_inclusion?: false`) grouping all resources mapped to that domain.
- **FR1.5**: Inject `domain: <DomainModule>` into the generated resource's `use Ash.Resource` declaration.

### FR2. Inverse Relationship Synthesis (`r2ml:inverseName`)
- **FR2.1**: Ingest optional `r2ml:inverseName` literal from SHACL property shapes.
- **FR2.2**: Persist `:inverse_name` in `AshR2RML.SemanticIR.Relationship`.
- **FR2.3**: Enforce collision-free admission in `AshR2RML.Admission.verify_inverse_names/1`:
  - Validate snake_case naming format (`~r/\A[a-z_][a-z0-9_]*\z/`).
  - Reject collisions with existing attributes or forward relationships on the destination resource.
  - Reject duplicate inverse declarations on the same target.
  - Refuse violations with typed code `:REFUSED_UNPROVEN_EQUIVALENCE`.
- **FR2.4**: Render synthesized inverses as `has_many <inverse_name>, <SourceModule>` with inverted `source_attribute` and `destination_attribute` keys.

### FR3. Modular Per-Resource Code Generation (`files: :per_resource`)
- **FR3.1**: Support `files: :single | :per_resource` in `AshR2RML.Ggen.compile_bundle/2` (defaulting to `:single`).
- **FR3.2**: In `:per_resource` mode, partition code into modular paths:
  - `generated/ash/<domain>/<resource_snake>.ex` for each resource.
  - `generated/ash/<domain>/<join_table_snake>.ex` for join tables.
  - `generated/ash/<domain_snake>.ex` for domain modules.
- **FR3.3**: Prepend standard provenance header to each file: `# GENERATED by ash_r2rml — DO NOT EDIT. Source: <shape_iri>`.
- **FR3.4**: Seal `receipts/ash-file-set.json` recording layout type, composite SHA-256 digest, and per-file SHA-256 digests.

### FR4. Bidirectional Castle-Bridge Trust Mirror
- **FR4.1**: Maintain 4 r2rml-side observations mirroring `xcb:bridge` in `ontology/castle_bridge_contract.ttl`.
- **FR4.2**: Verify contract shapes, cross-check mirrors against sibling pack ontologies, and enforce live HEAD alignment in `test/unit/castle_bridge_contract_test.exs`.
