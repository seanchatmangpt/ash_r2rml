# R2RML-261110-03: Multi-File Per-Resource Code Generation Layout & File-Set Receipts

**Title:** Multi-File Per-Resource Code Generation Layout & File-Set Receipts  
**Ticket Key:** `R2RML-261110-03`  
**Type:** Enhancement  
**Status:** IMPLEMENTED / VERIFIED  
**Priority:** Medium  
**Component:** `AshR2RML.Ggen`, `AshR2RML.SemanticRenderers`  
**Scope:**
- `lib/ash_r2rml/ggen.ex`
- `lib/ash_r2rml/semantic_renderers.ex`
- `test/ontology_first_domains_test.exs`

---

## 1. Context

In earlier releases, `AshR2RML.Ggen` bundled all generated Ash resources into a single monolithic file: `generated/ash/ontology_resources.ex`. While sufficient for toy projects, real-world Elixir architectures require one module per file, organized within domain subdirectories under `lib/`.

This enhancement introduces a configurable file bundling layout via `files: :per_resource`, allowing developers to generate a clean, idiomatic file tree where each resource, join table, and domain module resides in its own `.ex` file, sealed with a cryptographic file-set receipt.

---

## 2. Task Requirements

1. **Ggen Bundle Options (`lib/ash_r2rml/ggen.ex`)**:
   - Add `files: :single | :per_resource` option to `compile_bundle/2` and related bundle compilation functions.
   - Default `files:` option to `:single` to ensure full backward compatibility.
   - Refuse unsupported `files:` values with `{:error, %AshR2RML.Refusal{code: :REFUSED_UNPROVEN_EQUIVALENCE}}`.
2. **File Partitioning & Path Derivation**:
   - In `:per_resource` mode, map generated artifacts to discrete paths:
     - Entity resources: `generated/ash/<domain_dir>/<resource_snake>.ex`
     - Many-to-many join resources: `generated/ash/<domain_dir>/<join_table_snake>.ex`
     - Domain modules: `generated/ash/<domain_dir>.ex`
   - Prepend standard provenance header to every generated file:
     ```elixir
     # GENERATED by ash_r2rml — DO NOT EDIT. Source: <shape_iri>
     ```
3. **Cryptographic File-Set Manifest Receipt**:
   - In `:per_resource` mode, manufacture and seal `receipts/ash-file-set.json` recording:
     ```json
     {
       "layout": "per_resource",
       "single_source_ash_sha256": "<composite_sha256>",
       "files": {
         "generated/ash/facilities/facility.ex": "<file_sha256>",
         "generated/ash/facilities/client.ex": "<file_sha256>",
         "generated/ash/facilities.ex": "<file_sha256>"
       }
     }
     ```
   - Bind the receipt into the returned `%AshR2RML.Ggen.Bundle{}` struct.
4. **Automated Verification**:
   - Author tests in `test/ontology_first_domains_test.exs` asserting that:
     - `:single` layout produces `generated/ash/ontology_resources.ex`.
     - `:per_resource` layout produces separate files matching the manifest.
     - Invalid layout options return typed refusals.

---

## 3. Acceptance Criteria

- [ ] `files: :single` remains default and generates `generated/ash/ontology_resources.ex` backward-compatibly.
- [ ] `files: :per_resource` partitions resources into individual `.ex` files in `bundle.files`.
- [ ] Each generated file includes the `# GENERATED by ash_r2rml` header with source IRI.
- [ ] `receipts/ash-file-set.json` contains valid JSON with exact SHA-256 hashes of all emitted files.
- [ ] Passing an invalid option such as `files: :invalid` returns `{:error, %AshR2RML.Refusal{code: :REFUSED_UNPROVEN_EQUIVALENCE}}`.
- [ ] Generated files compile cleanly when evaluated via `Code.compile_string/2`.

---

## 4. Verification Method

Run the layout test suite:

```bash
mix test test/ontology_first_domains_test.exs
```
