## 5. Repository Release Doctrine & Policy Compliance

### 5.1 Why Direct Local Publishing is REFUSED
Executing `mix hex.publish --yes` directly from the local developer machine is typed as **`REFUSED(LOCAL_MUTATION_FORBIDDEN)`** under repository doctrine for the following decisive reasons:

1. **`R_missing_identity` (Chesterton Fence & Exact Commit Identity)**:
   Operating doctrine dictates $A = \mu(O^*)$ where $O^*$ must be grounded in an exact, immutable git commit SHA (`identity.subject_sha`). The local workstation currently operates on branch `dev` with uncommitted changes across working files. An artifact compiled from a dirty working tree lacks exact SHA identity, creating an untracked, irreproducible release that cannot be replayed from git history.

2. **`R_missing_authority` (Authority Ceilings & DO Isolation)**:
   Under `operating-doctrine.md` ("BRCE=唯一DO路。zero unreceipted actuation"), local agents and sessions operate under an authority ceiling of `:NONE` or `:CONSTRUCT` for production publication. Publication to a public registry (Hex.pm) is an irreversible actuation with global consequence (`remote_effects`). No individual session or unleased agent has authority to actuate Hex.pm releases without the formal release court.

3. **`R_missing_replay` (Deterministic Replayability)**:
   Repository law mandates byte-identical replay. Releases built on developer laptops are vulnerable to ambient toolchain drift, uncommitted dependencies, and local environment variables. The canonical release must be manufactured in a clean, isolated CI runner.

4. **Release Court Bypass**:
   Repository doctrine in `AGENTS.md` explicitly defines the release ladder:
   ```text
   mix format --check-formatted
   → mix compile --warnings-as-errors
   → unit tests
   → adversarial / negative tests
   → fortune5 tests
   → live integration
   → mix hex.build
   → GitHub Actions v* tags trigger CalVer publication (.github/workflows/release.yaml)
   ```
   Direct local publishing would bypass `.github/workflows/exact-head-release-court.yml` and `.github/workflows/release.yaml`, violating the admitted release gate.

The admitted, lawful release flow defined in `.github/workflows/release.yaml` and `.github/workflows/exact-head-release-court.yml` is structured as follows:

        │

        │
        ▼ 5. GitHub Actions: release.yaml triggered by `push: tags: ['v*']`
